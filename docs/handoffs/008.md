## Deviations and decisions

All are recorded with reasons in `docs/DEFERRED.md` (008 · CP1 to CP6). Items marked
**(spec silent)** are guesses that need your answer.

- **Tests 15 and 16, respaced over a year (pending sign-off).** As written, the four-day
  scenarios have XIRR roots of `1 + r ≈ 5.9e-87` and `2.7e79`. Both are outside decision 5's
  bracket and outside `decimal`, so XIRR is `null`.
  - **(a), built:** the same moves on days 0, 91, 182 and 365. TWR stays exactly 0. XIRR is
    `-0.6767…` (15) and `2.1693…` (16), so the timing effect has the sign the spec asks for.
    A third test pins the literal four-day scenarios as `null`.
  - **(b):** keep four days and assert `null` only. It keeps the dates and drops the point.
  - The spec is not edited (CP1, CP3).
- **Test 13, my reading of "a large late inflow".** Deposits followed by one late inflow
  never made Newton from 10% diverge on a gain. So the test uses `-100, +1000, -1000,
  +10 000` over 20 years. Newton leaves the bracket on step 5, and bisection finds the one
  root, `7.87298334620742`. It agrees with LibreOffice Calc's `XIRR()` (CP3).
- **Multiple XIRR roots (spec silent).** Flows that change sign more than once can have
  several roots. Newton returns the one it reaches from 10%, and bisection returns one in the
  bracket. An even number of roots in the bracket gives `null` (CP3).
- **IPCA + 6% compounds whole months, with no pro-rata (spec silent).** A month's rate lands
  on its row's date, the first of the month. So each end of a period is off by up to one
  month's rate. Manual step 4 checks CDI only. If IPCA + 6% must match a calculator to the
  day, it needs pro-rata by days (CP1).
- **Annualised TWR hidden for 365 days or less (pending).** The API always sends it. The
  headline and the benchmark table show it only past a year, as "annualise when the period
  exceeds one year" says. XIRR and the timing effect are always a year's rate. So over a short
  period the timing effect is a difference of two annualised figures, and it is large and
  noisy (1% over 10 days is about 44% a year). Confirm, or show annualised always, or hide the
  timing effect below some number of days (CP2, CP4, CP5).
- **260 points, not 262 (pending).** The spec says "at most 260 (weekly over 5 years)", but
  weekly over 5 years is 262. The cap wins. The stride is weekly up to 4.97 years, and an exact
  5 years gets an 8-day stride (CP4).
- **Assets with no row in the period are left out of both returns (spec silent).** An asset
  bought today, before its first close, has no value. Counting its buy would put a false
  loss in the XIRR (CP4).
- **`Returns:Benchmarks:*:Label` is unread.** The API sends codes, and the pt-BR names live
  in `labels.ts`, as CLAUDE.md says. Remove the config key, or keep it as documentation (CP3,
  CP4).
- **No expense red; orange used (pending).** The spec asks for "the same red as expenses",
  but the app has none. Expenses are ink, and the charts use `--chart-expense`, which is
  orange (005 · CP3 chose it for colour vision). A negative timing effect is that orange. It
  is about 3:1 on white, which passes WCAG AA only as large text. The 24px semibold headline
  qualifies. Confirm, or name a red token (CP5).
- **p.p. on the period's returns, also past a year (spec silent).** "Carteira menos
  referência" is `twr.total - benchmark.total`. Past a year, say if it should use the
  annualised figures (CP5).
- **Per-asset "Sem dados" rows (spec silent).** The per-asset table lists every position,
  including one with nothing in the period, which reads "Sem dados". Hide those rows, or keep
  them. The table makes one call per asset, because there is no list route (CP5).
- **The asset's returns page is not linked from `AssetPage` (spec silent).** The path
  `/investments/$assetId/returns` is mine. It is reached from the per-asset table only. Add
  a link on 007's asset page if wanted (CP5).
- **The period is not in the URL (spec silent).** It is lost on reload and cannot be
  shared (CP5).
- **USD flows at their own date's rate (spec silent).** Each USD flow converts at 007's rule
  for its own date, even when TWR moves it onto the asset's first row. That is the BRL the
  investor actually paid, and it keeps `r_fx` clean (CP2, CP3).
- **FX reported as 0 after a −100% return (spec silent).** When the native return is −100%,
  the identity holds for any `r_fx`. It is reported as 0 rather than dividing by zero (CP2).
- **Other spec gaps closed** (spec silent, each pinned by a test):
  - The base day is `from - 1`, or the first contribution's day at inception. The TWR, the
    benchmarks and the chart share it (CP1, CP4).
  - XIRR opens with `-V(from - 1)`. An asset with no row then opens at zero instead (CP4).
  - A flow dated before its asset's first row lands on that row (CP2).
  - Dividends and JCP are net of fees, in TWR and XIRR (CP1).
  - SELIC is returned too. The spec's config lists it, but its example does not (CP1).
  - The end of a period is clamped to the last daily row (CP4).
  - The empty state is a 200 of nulls, not a 404 (CP4).
- **Invented pt-BR copy.** The 400 messages (CP4) and every screen label (CP5) are listed in
  DEFERRED. The spec's own strings ("Efeito do timing" and its sentence) are verbatim.
- **E2E fakes (CP6).** A fake close is 10 on the sync's `to`, one cent lower for each day
  before it, and 5 from 500 days back. The latest close is still 10, so 006's and 007's E2E
  are unchanged. Benchmarks are unchanged: one 0.05 per series, dated `to`.

## UI bugs found by the first real-browser run (CP6)

Both were fixed with a failing test first.

- A one-day period read "1 dias". It now reads "1 dia" (`ReturnsReport`).
- The chart's Y axis rounded ticks to whole numbers, so a 100–103 range printed "102"
  twice. Ticks now keep up to two decimals (`formatIndexTick` in `lib/rates.ts`).

Seen and not changed:

- The tooltip lists series in Recharts' order (CDI, Carteira, IPCA + 6%, SELIC), not with the
  portfolio first.
- When an asset's first close comes after its buy, the period line shows the buy's date as
  the start while `days` counts from the first close ("25/08 a 24/09 · 1 dia"). This is
  CP4's API semantics. Say if `period.from` should be the base day.

## Known debts

- Nothing is checked against a real portfolio, a spreadsheet's `XIRR()` on your flows, or a
  CDI calculator yet (manual steps 1–5).
- **One call per asset** in the per-asset table. A list route is a small change if it gets
  slow.
- **JSON numbers are float64** in the browser. The API rounds rates to 10 places and index
  values to 6, so nothing visible is lost (CP4, CP5).
- **Fake closes depend on the run that fetched them.** A close is counted back from that
  run's `to`, and the sync never refetches a stored day. So a ticker synced on two days has a
  step between them. E2E 36 uses a new ticker every run, so it is backfilled in one go.
- **The E2E database grows faster.** Each new ticker is backfilled with five years of fake
  closes (about 1 826 rows). Each run adds three: two from `market-data.spec.ts` and one from
  test 36. That is harmless at this scale.
- **Benchmarks in the E2E database are sparse.** They have one row per day a run happened.
  So Dólar and S&P 500 (IVVB11) read "Sem dados" in test 36, because no row exists before the
  base day. The test does not assert them.
- Carried from 007: the ARCHITECTURE Investments block, CLAUDE.md's shared-table list, no
  composite FK, and the rest of 007's "Known debts".

## Lessons

- **Check a scenario's numbers before building its test.** Tests 15 and 16 could not pass as
  written. Computing the XIRR root outside the code base in CP1 found it three checkpoints
  before the test was due.
- **`decimal` has no `Pow`, and that is fine.** A small `Exp`/`Ln` kept decision 10 whole,
  with no `double` anywhere, and matched a 40-digit reference.
- **jsdom hides layout bugs.** Both CP6 fixes were invisible to 142 unit tests and obvious in
  one screenshot. A throwaway screenshot pass over a new page is cheap.
- **A kept E2E database needs fresh fixtures for time-shaped data.** A reused ticker carries
  every earlier run's closes, so test 36 registers its own.
