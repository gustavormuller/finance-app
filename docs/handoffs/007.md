## Deviations and decisions

All are recorded with reasons in `docs/DEFERRED.md` (007 · CP1 to CP5). Items marked
**(spec silent)** are guesses that need your answer.

- **Rounding against the broker.** Full `decimal` precision in the calculator. It rounds
  once, at the column: the average to 8 places, BRL to 2, half to even. It has not been
  checked against a real preço médio. Manual step 2 decides it. If it is a cent off, the
  fix is at the column boundary, not in the formulas (CP2).
- **USD conversion (spec silent).**
  - `CostBasisBrl` uses each buy's FX, as the spec says.
  - `realisedBrl` and `dividendsBrl` convert each event at **its own date's** USDBRL: the
    latest on or before it, or the earliest after it. Today's rate is not used (CP3).
  - A USD buy dated before the first known rate is costed at the earliest later rate (CP2).
- **Nightly rebuild range (spec silent on the edges).**
  - It starts from yesterday, as the spec says.
  - It starts earlier where rows stop before yesterday (missed nights), or start after the
    first day that can be valued (a history backfilled late) (CP3).
- **Manual sync also rebuilds (spec silent).** Both triggers run the rebuild after the sync,
  inside `MarketDataSyncGate`. Otherwise a manual sync's closes would wait for the next
  night (CP3).
- **409 on a movement DELETE (spec silent).** A delete that would uncover a later sell is a
  409 with the rule's text. A POST or PUT that breaks the rule is a 400 on `quantity` (CP3).
- **`POST /rebuild` answers 202, but synchronously.** The work is done before the answer, and
  the body is `{ assetsRebuilt, rowsWritten }`. It is 202 because the spec says 202; 200
  would be more honest (CP3).
- **Silent decimal rounding, and a 500 on overflow.** PostgreSQL rounds a quantity or unit
  price past 8 places, and an amount or fee past 2, without a word. A value past the
  column's range is a 500. Refusing either needs new pt-BR copy (CP3).
- **JSON number precision.** The form sends float64 numbers, which are exact to 15
  significant digits; the columns hold 18. Fixing it means sending strings with
  `AllowReadingFromString`. 003's amounts have the same limit (CP4).
- **Zero positions hidden (spec silent).** A position at quantity 0 is hidden from
  `/investments` by default. That covers an asset with no movement yet and one sold to
  zero. "Mostrar ativos sem posição (N)" shows them, and adding an asset opens it at once.
  E2E 33 relies on this (CP4).
- **Stale price (spec silent on holidays).** "Older than 3 business days" is read as more
  than 3 weekdays in `(priceDate, today]`, in the browser's local date. Holidays count as
  business days, so a Friday close after Carnival is flagged a day early (CP4).
- **Split fields (spec silent).** The form shows only the quantity. Price is 0 by
  decision 3. Fees are sent as 0, and the calculator ignores them on a Split anyway (CP2,
  CP4).
- **Other spec gaps closed in CP2** (spec silent):
  - Fees on a Dividend/Jcp are subtracted from income.
  - Fields irrelevant to the kind are stored as zero.
  - Buy/Sell `UnitPrice` has no rule.
  - A split on a zero position is allowed.
- **Invented pt-BR copy.** None of it comes from the spec; it is listed in full in
  DEFERRED 007 · CP2, CP3 and CP4. Examples:
  - The fees rule, `Taxas não podem ser negativas`.
  - The 409s, such as `Você já possui este ativo na carteira.` and `O ativo tem
    movimentações. Exclua-as antes de remover o ativo.`
  - The `Snapshots` summary label, "Posições da carteira".
  - Every screen label and message, and the kind labels (Compra, Venda, Dividendo, JCP,
    Desdobramento).
- **ARCHITECTURE.md's Investments data-model block is stale.** It still lists `assets` with
  ticker, name, `fixed_income`, currency and `benchmark_hint`, and the kind
  `amortization`. The spec replaced it with `MarketAssetId` → `MarketAssets`, and added
  `Movement.Amount`, `Movement.Currency` and the full `PortfolioDaily`. It is a data model,
  not an ADR, so it was not edited. It needs a one-block edit. `benchmark_hint` has no
  replacement (CP1).
- **CLAUDE.md's shared-table list** names `prices` and `benchmarks` only. `MarketAssets` and
  `SyncRuns` are shared too (carried from 006). 007 adds no shared table: `PortfolioDaily`
  copies a price per user, and that copy is user-owned derived data (CP1).
- **E2E and the sync gate (CP5).** The investments spec runs in its own Playwright project,
  which depends on the `market-data` project. So it never overlaps test 26, and test 26
  still asserts its 202 unchanged.
  - Its three tests run in order (`mode: 'default'`).
  - Each one waits out a 429, because the rebuild after the previous run's sync can still
    hold the gate after that run reads `Succeeded`.
  - A failing `market-data` project makes the investments tests "did not run" rather than
    fail.
- **E2E 33 keeps a dividend** when the buy is deleted. It answers CP4's open question: the
  rules allow income on a zero position, and the row is hidden, not removed.

## Known debts

- Nothing is checked against a real broker yet: the rounding, the USD cost basis and the
  current value (see Status).
- **No composite FK** holds `Movement.UserId = Asset.UserId` in the database. The endpoint
  resolves the asset through the filter first (test 17). The hardening is optional (CP1).
- **An asset delete racing a movement write** is a 500 instead of a 409. The FK is not
  caught (CP3).
- **A manual run reads `Succeeded` before its `Snapshots` section is written.**
  `/market-data` stops polling a few hundred milliseconds early. The section appears on the
  next refetch (CP3).
- **The E2E database grows.** Each run leaves three more PETR4 holders and a catalogue entry
  per market-data test. So each manual sync's after-sync rebuild does a little more (4, 5,
  6, 7 assets across one run). It is harmless at this scale. A reset would need the
  connection string, which `verify-e2e.sh` does not have (006 · CP5).
- The chart reuses the dashboard's `--chart-income` blue. A neutral series token would read
  better (CP4).
- Carried from 006: provider keys, captured fixtures, SGS codes, container `TZ`, and
  nothing deactivates a catalogue entry. Carried from 005: English 400 titles on two pages,
  and five C# files without a BOM.

## Starting spec 008 (returns)

Read `specs/008-returns.md`, this file, and the 006 and 007 entries in DEFERRED. Plan the
checkpoints in STATUS.md as before. The baseline is .NET 611, web 115, E2E 21.

- **What `PortfolioDaily` gives you.** One row per calendar day per asset, from
  `max(first movement, first close)` to today (UTC).
  - The rows hold `Quantity`, `AverageCost` (8 places), `Price` (native, carried),
    `PriceDate`, `FxRate` (`1` for BRL), `ValueBrl` and `CostBasisBrl` (2 places).
  - A position sold to zero keeps rows at `ValueBrl` 0, so 008's "skip days where
    `V_{d−1}` = 0" applies.
  - Days before an asset's first close have no row at all, even if a buy is dated there.
    Decide how `F_d` on such a day enters TWR.
- **Flows are not in `PortfolioDaily`.** `D_d` and `F_d` come from `Movements`.
  - Convert a USD flow with the same rule the rows and positions use: the latest USDBRL on
    or before the date, or the earliest after it. Otherwise `r_fx` will not decompose
    cleanly.
  - `dividendsBrl` is **net of fees** (CP2). Decide whether 008's `D_d` and its XIRR
    `+dividends` take gross or net, and say so.
  - A Split is not a flow (decision 3), and the calculator ignores its fees.
- **Reuse the calculator.** `PositionCalculator.Calculate(movements, fxOn?)` already yields
  each step's realised gain and income in native currency. `SnapshotBuilder` shows how FX is
  looked up.
- **Benchmarks.** 008's `Returns:Benchmarks` types must match 006's typed `BenchmarkUnit`
  (`PercentPerDay`, `PercentPerMonth`, `Level`) in `MarketData:Bcb:Series`. Derive or
  assert the match; do not keep a second hand-written copy.
  - IPCA is monthly and dated the first of its month.
  - IVVB11 is a brapi close copied into `Benchmarks`, and already embeds FX.
- **Precision.** Every stored value reaches C# as `decimal`, and `Money` pins 2 places. Rates
  and index values are measurements, so they are raw `decimal`, like 007's prices
  (decision 10).
- **E2E.** Under `FakeProviders` every close is 10 and every benchmark 0.05, both dated
  yesterday, so a real return is always 0. If 008's E2E needs a non-trivial series, the
  fakes need a shape, or the test must accept 0.
  - An 008 spec that triggers a sync must join the `investments` project's rule: depend on
    `market-data`, run its tests in order, and wait out a 429.

## Lessons

- **A sync gate is shared state across spec files.** `fullyParallel` makes any two syncing
  files race. A Playwright project dependency serialises them without touching the test
  that asserts the 202.
- **"Succeeded" is not "done" when work follows the status.** The rebuild after a sync still
  holds the gate after the run reads `Succeeded`, so anything that syncs twice in a row
  must wait out a 429.
- **Decide rounding at one boundary.** Carrying full precision and rounding at the column
  kept the calculator, the rows and the position endpoint consistent with each other.
