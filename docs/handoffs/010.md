## Pending a human: the runbook

Follow `specs/010-deploy.md` in order, and stop at a failed check. These are the changes
from the spec's text:

1. **Instance, hardening and Docker (steps 1–3).** As written.
2. **Repo and secrets (step 4).**
   - Copy `deploy/.env.example` to `/opt/finance/.env`, fill it in, and `chmod 600` it.
     `deploy.sh` refuses the file otherwise.
   - Include `Ai__Anthropic__ApiKey`, 006's three market-data keys and `AGE_PUBLIC_KEY`.
   - `Ai__FakeProvider` and `MarketData__FakeProviders` must be absent.
3. **Tunnel and Google (steps 5–6).** As written. The tunnel's public hostname points at
   `http://caddy:80`.
4. **First deploy (step 7).** Run `./deploy/deploy.sh` from `/opt/finance/src`. It builds
   the web in a Node container, so Node is not needed on the host. Check that `smoke.sh`
   passes through Cloudflare. If bot protection challenges curl, relax it for the smoke.
5. **First login (step 8).** After `docker compose restart api`, you should still be
   signed in. The key ring is on the `dpkeys` volume.
6. **Backups (step 9).**
   - Install `age` and `rclone`, and create the remote `backup`.
   - Put the public key in `.env` as `AGE_PUBLIC_KEY`, **not** in `backup.sh`.
   - The cron user needs the `docker` group and write access to
     `/var/log/finance-backup.log`.
   - **Copy `backup.key` off the server.**
7. **Restore drill (step 10), required.** The file is at `backup:finance-backup/daily/<latest>`.
   Add `--no-owner` to the `pg_restore`.
8. **Monitoring and second deploy (steps 11–12).** As written. Rollback is
   `./deploy/deploy.sh <tag>`.
9. **After it works:** update ARCHITECTURE.md's deploy sections (a DoD item, below), pin
   `cloudflared`, and tag the deployed commit.

## Decisions to confirm (details in DEFERRED 010)

- **Forced by the image:** the `migrate` argument replaces `dotnet ef database update`, which
  the runtime image cannot run (CP1).
- **Needed for https to reach the API:** Caddy trusts private-range peers (CP2), and the API
  also honours `X-Forwarded-For`, so the sign-in limit counts browsers (CP1).
- **Spec silent:**
  - The pinned subnet `172.30.0.0/24` (CP2).
  - `webdist` as a bind mount (CP2).
  - The bash health check (CP2).
  - The Node container build (CP3).
  - The web published after `up -d` (CP3).
  - The pull only on a branch, and the re-exec (CP3).
  - The backup layout and UTC dates (CP3).
- **Still open from 006:** the container `TZ`. It is unset (UTC), so the nightly sync runs
  at 00:00 in Brasília.
- **Suggest vs Cloudflare's 100 s:** a worst-case 200-row suggest (150 s) gets a 524. Accept
  it, cap the rows, or make it a job (CP2).
- **The spec's reason is off:** the session cookie is always `Secure`. `X-Forwarded-Proto`
  matters for the Google `redirect_uri` (CP1). The spec was not edited.
