# 022 — Installable PWA

## Goal

The app can be installed from the browser on a phone or a desktop and opens in its own window,
with its own icon and the theme's colours (ARCHITECTURE.md, Phase 6; "React Native: a PWA
solves it"). A small service worker makes the installed app open even when the server cannot be
reached, showing the app's own error states, and it never stores a byte of anyone's financial
data.

## Decisions made in this spec

Marked **(review)** where the spec picked a default a person should confirm.

| # | Question | Decision |
|---|---|---|
| 1 | Names | `name` **Finanças Pessoais** (the heading), `short_name` **Finanças** (fits under a home-screen icon), `description` **Suas finanças e investimentos em um só lugar.** `lang` `pt-BR`, `dir` `ltr`. **(review)** |
| 2 | Window | `display: standalone`, `start_url: "/"`, `scope: "/"`, `id: "/"`. The whole origin is in scope, so the Google callback (`/api/auth/google/callback`) comes back into the app's window. |
| 3 | Manifest colours | `background_color` and `theme_color` are **`#0B0C12`**, the Obsidiana ground (012). A manifest cannot follow the theme: a dark splash before a light page is a blink, a white splash before a dark page is the flash 012 exists to avoid. **(review)** |
| 4 | Toolbar colour in the page | Two `theme-color` metas, each theme's ground: `#F1F2F7` for `(prefers-color-scheme: light)`, `#0B0C12` for `dark`. An explicit Claro or Escuro overrules the system, so the script in `index.html` (before the first paint) and `applyTheme` in `lib/theme.ts` (on every change) set both metas to the colour of the theme actually applied. |
| 5 | Icon | No brand asset exists. The mark is **"F."**: the F of Finanças in the text colour `#F4F5F8`, drawn as three rectangles (no font), followed by the violet full stop `#8B73FF` that already ends the heading ("Finanças Pessoais."), on the Obsidiana ground with its `#1B1F3B` glow. The regular icon is a rounded tile; the maskable and Apple icons are full-bleed with the mark scaled to 90%, well inside the maskable safe zone (the central circle of 80% diameter). **(review)** |
| 6 | Icon files | Sources: `public/favicon.svg` (the tile) and `public/icons/icon-maskable.svg` (full-bleed). PNGs rasterised from them by `web/scripts/icons.ts` through the Playwright Chromium the E2E suite already installs; no image dependency. Files: `icons/icon-192.png`, `icons/icon-512.png`, `icons/icon-maskable-512.png`, `icons/apple-touch-icon.png` (180), `icons/favicon-32.png`. |
| 7 | Favicon and iOS | `<link rel="icon">` to the SVG and to the 32 px PNG (for browsers without SVG favicons, Safari among them), `apple-touch-icon` at 180, `apple-mobile-web-app-capable` (and Chrome's `mobile-web-app-capable`), `apple-mobile-web-app-title` **Finanças**, `apple-mobile-web-app-status-bar-style` **default** (the content does not run under the status bar, so no safe-area padding is needed). **(review)** |
| 8 | Service worker implementation | **Hand-written** (`web/src/sw/sw.ts`, about 80 lines) plus a small Vite plugin in `vite.config.ts` that bundles it on its own into `dist/sw.js`, a classic script, with the build's file list and a version. No dependency. `vite-plugin-pwa` 1.3.0 does declare `vite ^8`, but it brings `workbox-build` (37 direct dependencies, Babel, Rollup and terser among them) into a Rolldown build, and its routing would be Workbox configuration; here the one rule that matters, "never touch `/api`", reads as four lines of code with a unit test. **(review)** |
| 9 | What is ever written to Cache Storage | **Only the build's own files, at install**: `index.html` and every file under `dist/assets/` (the entry, the CSS, the fonts, and lazy chunks when there are any). Nothing is cached at runtime: no API response, no page. So there is nothing personal to clear on sign-out or on account deletion (ADR-013), and the worker never needs to know who is signed in. |
| 10 | Routing | A pure function, `routeFor(request, origin)` in `web/src/sw/routing.ts`; the table is under **Behaviour**. `network-only` means no `respondWith` at all: the browser handles the request as if there were no worker. |
| 11 | Navigations | **Network-first, 3 s timeout**; on a network failure, the timeout, or a 5xx, the precached `index.html` of the worker's own build answers. A 5xx on a navigation is Cloudflare or Caddy, never the app (every app route is `index.html`), so the installed app still opens on its error states when the box is down. The network answer is never cached. **(review)** |
| 12 | Updates | The version is a SHA-256 over the name and bytes of every precached file, so any change to the build, `index.html` included, makes `sw.js` differ byte for byte. The browser compares `sw.js` on every navigation (bypassing its HTTP cache for the worker script), installs the new build into `finance-<version>`, **`skipWaiting()`** and, on activate, **`clients.claim()`**. Activate deletes every `finance-*` cache except the new one **and the previous one**: a tab still running the previous build, now controlled by the new worker, still loads that build's lazy chunks although the deploy deleted them from disk. A tab two deploys old can fail on a lazy chunk; reloading fixes it. No "update available" UI: navigations are network-first, so a reload always gets the new shell, and nothing on screen depends on which worker is running. **(review)** |
| 13 | Registration | `navigator.serviceWorker.register('/sw.js')` after `load`, only when `import.meta.env.PROD`. The dev server, HMR and the dev-server E2E suite never see a worker. |
| 14 | Caddy | `/assets/*`: `Cache-Control: public, max-age=31536000, immutable` on a 200 only, and a missing file is a **404** instead of `index.html` (otherwise a stale chunk request gets HTML, and an edge would keep that HTML for a year under a script's name). Every other static response (`index.html` for every route, `sw.js`, `manifest.webmanifest`, the icons): `Cache-Control: no-cache`, revalidated on every load. `sw.js` and `manifest.webmanifest` exist as files, so `try_files` serves them as themselves: `text/javascript` and `application/manifest+json` (checked against `caddy:2-alpine` v2.11.4). `/api/*` and `/health` are untouched. **(review)** |
| 15 | Cloudflare | No configuration change: Cloudflare does not cache a response marked `no-cache`, and HTML and `.webmanifest` are not in its default cached extensions anyway. `/assets/*` may be cached at the edge, which is safe. The zone's *Browser Cache TTL* must stay **Respect Existing Headers**; a "cache everything" rule would have to exclude `/`, `/index.html`, `/sw.js` and `/manifest.webmanifest`. **(review)** |
| 16 | Where the worker's end-to-end test lives | Its own Playwright config, `web/playwright.pwa.config.ts`, and folder, `web/e2e-pwa/`: it needs a production build, stops the server to go offline and rebuilds mid-run, none of which fits the dev-server suite. `npm run e2e:pwa`. Not wired into `scripts/verify-e2e.sh`. **(review)** |

## Out of scope

- Offline data, or any read cache of API responses
- Background sync, push notifications, periodic sync
- An install button or prompt, an offline banner, an "update available" notice
- App-store packaging (TWA, native wrappers), screenshots and richer install UI in the manifest
- Navigation preload

## Behaviour

**Routing** (`routeFor`), first match wins:

| Request | Route |
|---|---|
| any method but `GET` | `network-only` |
| another origin (Google, anything) | `network-only` |
| `/api`, `/api/*`, `/health`, `/health/*`, matched case-insensitively on the decoded path, as Caddy matches | `network-only`, navigations included (`/api/auth/google`, `/api/auth/google/callback?code=…`) |
| any other navigation (`/`, `/transactions?from=…`, `/investments/42`) | `network-first-shell` |
| `/assets/*` | `cache-first` |
| everything else (`/sw.js`, `/manifest.webmanifest`, icons) | `network-only` |

`cache-first` looks in every `finance-*` cache (the names are content-hashed, so any copy is the
right one) and falls back to the network without storing the answer.

**First visit.** The page loads normally; after `load` the worker registers, precaches the build
(about 1.2 MB before compression today, fetched with `cache: 'no-cache'` so an old `index.html`
in the HTTP cache cannot slip in), activates and claims the page.

**Offline, or the server down.** Opening the installed app, or reloading any app route, serves
the precached shell; the app then does what it already does when the API cannot be reached: the
sign-in guard sends the visitor to `/login`, the footer reads `degraded` / `unreachable`.
`/api/*` requests fail as they would without a worker.

**A deploy.** See decision 12. The deploy script deletes the old files before copying the new
ones; an open tab of the previous build keeps working from the previous cache.

**Sign-out, account deletion.** Nothing to do: Cache Storage holds only the build (decision 9).

**Removing the worker, if it ever misbehaves.** Deploy a `sw.js` whose install calls
`skipWaiting()` and whose activate deletes every `finance-*` cache and calls
`self.registration.unregister()`, and keep serving it for a few weeks. Deleting `sw.js` instead
leaves installed workers running until the browser gives up on them.

## Test plan

### Unit — `web`

1. `routeFor`: `/api/auth/google/callback?code=…` and `/api/auth/google` as navigations,
   `/api/transactions` as a fetch and as a POST, `/API/Transactions`, `/%61pi/auth/me` and
   `/health` are `network-only`; `/assets/index-abc123.js` and a stylesheet are `cache-first`;
   `/transactions?from=…&to=…`, `/` and `/apiary` as navigations are `network-first-shell`; a
   cross-origin navigation and asset, `/sw.js`, `/manifest.webmanifest` and an icon are
   `network-only`; a `HEAD` for an asset is `network-only`
2. `cachesToDelete`: keeps the current cache and the one created just before it, deletes the
   older ones, never names a cache without the `finance-` prefix
3. The manifest parses; names, `lang`, `id`, `start_url`, `scope`, `display` as decided; icons
   for 192 `any`, 512 `any` and 512 `maskable`, each file present in `public/` with the pixel size
   it declares; `background_color` and `theme_color` are the dark ground in `index.css`
4. `index.html` links the manifest, both favicons, the Apple icon (files present, sizes right)
   and carries the iOS metas; its two `theme-color` metas are the grounds in `index.css`
5. Choosing Escuro under a light system sets both `theme-color` metas to `#0b0c12`, Claro to
   `#f1f2f7`; Sistema follows the system
6. `registerServiceWorker` registers nothing outside a production build, and in one registers
   `/sw.js` once the page has loaded

### E2E — `web/e2e` (dev server)

7. The theme test: after Escuro and a reload, both `theme-color` metas are `#0b0c12`; after
   Claro, `#f1f2f7`

Every existing E2E test passes unchanged, with no worker registered.

### Service worker end to end — `web/e2e-pwa` (production build, `vite preview`)

The spec builds the app, serves `dist` with `vite preview` (which inherits `server.proxy`, so
`/api` reaches the API at `API_URL`), and drives full Chromium in new headless mode.

8. The worker registers and controls the page
9. After the dev sign-in, creating an account and loading the dashboard, transactions, accounts
   and investments: Cache Storage holds exactly one cache, whose entries are exactly `/index.html`
   and every file in `dist/assets/`; no entry is under `/api` or `/health`; no cached body
   contains the account's name or the user's e-mail
10. With the preview server stopped, loading `/transactions` shows the app (the heading, the
    footer's `degraded`), answered by the worker, not the browser's error page
11. The browser reports no installability errors (`Page.getInstallabilityErrors` over CDP) and
    parses the manifest without errors (`Page.getAppManifest`)
12. A second build with one changed module (`e2e-pwa/second-build.config.ts`), written over
    `dist` while the page is open: after one reload a second `finance-*` cache appears and the
    first is kept; the first build's entry chunk, gone from disk, is still served; with the
    server stopped again, a reload runs the second build's code from its cache

## End-to-end verification

```
bash scripts/verify.sh

# the dev-server suite, against an isolated API and database
BASE_URL=http://localhost:5173 npx playwright test

# the worker (from web/): an API on API_URL whose App__Origin is http://localhost:$PREVIEW_PORT
API_URL=http://localhost:5080 PREVIEW_PORT=4173 npm run e2e:pwa
```

After deploying:

1. `curl -sI https://<domain>/sw.js`: `200`, `content-type: text/javascript`,
   `cache-control: no-cache`, `cf-cache-status` not `HIT`. The same for `/manifest.webmanifest`
   with `application/manifest+json`; `/assets/<a real file>` has `immutable`; `/assets/nope.js`
   is `404`
2. Chrome desktop: the install icon appears in the address bar; the installed window has the
   icon, the name and a toolbar in the theme's colour, following Claro and Escuro
3. Android (Chrome): install, open from the home screen, **sign in with Google from the
   installed app**: the session lands in the app's window. Airplane mode, reopen: the app's
   login page with `degraded`, not Chrome's dinosaur
4. iPhone (Safari → Compartilhar → Adicionar à Tela de Início): the icon, the name "Finanças",
   standalone window, Google sign-in completes inside it
5. Deploy again: the open installed app keeps working; after a reload it runs the new build

## Definition of done

- `verify.sh` green; the dev-server E2E suite green on an isolated database
- Tests 1–12 exist and pass
- No `/api` or `/health` URL can reach Cache Storage, by construction (decision 9) and by test 9
- Icons checked by eye at 32, 192 and 512, maskable under a circular mask, in both themes' contexts
